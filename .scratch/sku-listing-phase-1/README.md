## 执行约定

- 每个任务单独记录状态、实施结果和验证证据，沿用本仓库本地任务系统。ready-for-agent 表示需求可执行，不表示前置依赖已解决。
- 按依赖领取任务。当前可开始 06、08、09、11；按编号推进时从 06 开始。无需将没有依赖的两条业务线强制串行，但不能跳过下表中的真实阻塞项。
- 每项完整交付网页和 API 行为；数据结构、持久化、权限、必要迁移与测试随该业务切片一起完成，不再拆成只有后端或只有页面的横向任务。
- 全部验收以主规格为准。当前数据均为测试数据，允许在备份及范围核对后按正式模型纠正；保留其他工作区修改，不自动清库或部署。

## 总体验收出口

- 完成一次商品建档、规格生成、启用、采购分批收货到可用库存，并核对库存唯一过账及采购来源追溯。
- 完成 SKU 文件混合新增/更新、新 SPU 建档以及失败整批回滚；确认草稿状态、空值语义及锁定规则。
- 完成单/批人工配对和两种 Excel 配对，覆盖当前关系后证明历史订单快照不变。
- 完成原始订单整单待配对、人工重处理、重复/并发重试与标准订单跳转，并证明未自动支付、预占或发货。
- 完成停用后的新需求阻止及存量原范围履约、草稿资料刷新、早期 SKU 更正与各类有副作用订单拒绝更正。
- 每项给出 HTTP API 与网页证据，关键事务/唯一性在实际数据库验证；迁移可恢复且不破坏既有 WMS 闭环。PDA 和真实亚马逊接入不在本期验收范围。
