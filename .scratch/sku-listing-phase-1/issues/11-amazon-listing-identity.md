# 11: Amazon Listing 标识与统一查询入口

Status: ready-for-agent

**What to build:** 运营人员在统一 Listing 页面准确查看和补录店铺、站点、MSKU、ASIN、FNSKU，旧入口跳转到相同业务页面，为商品配对提供明确对象。

**Blocked by:** None (can start immediately)

- [ ] 「销售运营 → Listing 管理」为唯一业务入口，旧「产品开发 → Listing」跳转并保留有效筛选。复用现有共用页面改动，按用户实际权限提供读写能力，不复制一套展示数据。
- [ ] 每条可配对渠道商品可明确识别租户、Amazon 渠道、店铺、站点和 MSKU；同一范围内不重复。SPU 关联或现有 marketplaceListingId 不能直接冒充完整商品配对标识。
- [ ] MSKU 按平台原值存储及精确识别，不套用本地编码规范化；ASIN、FNSKU 可空并可后补。Listing 的在售状态、配对状态、本地 SKU 状态分别展示。
- [ ] 支持现有/手工维护的 Amazon Listing 资料建档或补录，无本地配对的 Listing 可以存在；通过既有 Listing 维护权限控制此类资料写入，不把商品配对权限扩大成任意刊登维护权限。
- [ ] 可按店铺、站点、MSKU、ASIN、本地 SKU 和配对状态查询；从店铺跳转后筛选正确，其他未实现渠道的既有记录不被删除或篡改。
- [ ] 对现有聚合 Listing 和渠道映射先列出可推导关系、缺失与冲突，再兼容扩展到可售 MSKU 身份；没有证据时不把一个 SPU 或 ASIN 随意当成单个卖家商品。
- [ ] 正确消费当前接口数组/分页结构及稳定 ID，保留已修复的查询与跳转；空数据、请求错误及越权明确反馈，不以空数组掩盖契约问题。
- [ ] HTTP API 验证标识唯一、MSKU 原值、店铺/站点隔离、手工补录及查询；网页从两个入口访问同一业务页、筛选、补录平台标识并刷新核对。全过程不调用亚马逊接口。

## Comments

本任务可基于现有主数据独立进行。配对操作、候选及历史由 12 接入；本任务不将「手工刊登资料」扩展为真实远端发布或同步。
