# 01: SKU 草稿建档与两个维护入口

Status: resolved

**What to build:** 商品维护人员可从独立「SKU 管理」列表及 SPU 详情新增、查看、编辑草稿。普通商品支持一步创建 SPU 和 SKU，变体可选择既有 SPU 建档。

**Blocked by:** None (can start immediately)

- [x] 提供跨 SPU 的 SKU 查询，按本地编码、名称、所属 SPU 和状态定位商品；SPU 详情中的 SKU 列表与独立列表读取同一份真实数据。
- [x] 手输编码或一键生成；后端统一去首尾空白并转大写，只允许字母、数字、连字符、下划线。` mug-01 ` 和 `MUG-01` 在同一租户冲突，不同租户隔离。
- [x] 普通商品一步建档后得到一个 SPU 和一个 SKU；任一部分失败不留下孤立半条数据。已有 SPU 下可以新增草稿，不按名称模糊推断归属。
- [x] 默认保存 DRAFT，允许分阶段补资料；创建请求不再强制填写重量、申报金额及币种。稳定内部身份、归属可追踪，尚不完整的资料在详情可辨识。
- [x] 分类、品牌由 SPU 提供并在 SKU 显示继承结果；维护共用字段走 SPU 入口，不在 SKU 上存储另一份独立分类/品牌。
- [x] 提供 SKU 名称及基本库存单位的维护与显示；每个 SKU 使用一个固定单位，商品界面区分本地编码、内部 ID、SPU 编码，不将本地编码标成平台 MSKU。
- [x] 新增和编辑在后端要求商品维护权限并校验租户；失败显示可理解原因，网页支持加载、空数据和请求错误反馈。已有已启用/引用记录不能通过本任务编辑入口改变身份，完整生命周期由 02 补齐。
- [x] 保留工作区已有商品页面及接口类型修正，按照实际数组/分页结构和 spuId/skuId 联动，不使用硬编码演示列表。
- [x] 用 HTTP API 验证规范化唯一性、两种建档方式、事务失败、权限与租户隔离；网页完成建档、跨入口查看及草稿编辑，数据刷新后仍一致。

## Comments

规格适用范围见本需求 spec；后续规格字典、批量生成、图片和导入分别由独立任务补齐，不在本任务提前建立第二套商品模型。

## Answer

已实现独立「产品开发 → SKU管理」及 SPU 详情内的共用维护入口。两处使用同一份持久化 SKU 数据；支持跨 SPU 查询、规范化本地编码、生成编码、草稿查看/编辑、普通商品一步创建 SPU+SKU、继承分类品牌、基本库存单位及缺项提示。创建不要求重量或申报资料。主数据及共用字典写操作要求 `pdm:product:write`，产品页与 SKU 页均按权限显示操作；父级编辑校验字典租户并刷新 SKU 缓存。无品牌 SPU 可以继续维护。

本切片的编辑保留编码、所属 SPU 和已确定的库存单位；完整引用判定及允许范围内的身份修改由任务 02 承接。已有非草稿商品在该草稿入口只读。首次补填单位在事务内锁定 SKU，防止两个请求先后写入不同库存口径。
