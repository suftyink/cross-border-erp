# 16: 无资金及履约影响订单的 SKU 更正

Status: ready-for-agent

**What to build:** 有权限的订单人员在真正尚未发生资金、库存或仓储影响的标准订单上，填写原因并受控更正商品，保留前后快照与完整审计。

**Blocked by:** 15：平台原始订单待配对与手动重处理。

- [ ] 网页及后端仅允许同时满足未付款、无相关财务记录、无任何预占、无旧履约计划、无 WMS 作业、无实际发货的订单更正；按实际关联记录判断，不能只看订单主状态。
- [ ] 未付款但已有旧履约计划、主状态 PAID 但已部分实发、仓储任务已存在等反例均拒绝直接改行，且说明阻塞原因；不自动撤销、冲销、退检或补偿这些业务。
- [ ] 操作者具有相应订单更正及店铺数据权限；选择本租户已启用目标 SKU，填写原因并预览原→新商品及资料影响，确认后才更新。
- [ ] 保存旧/新 SKU、旧/新商品及配对相关快照、操作者、时间和原因。原始平台 MSKU 负载保持不变，不能把人工更正伪装成原始解析结果；不自动修改当前全局配对。
- [ ] 重新校验商品、风险及该订单既有成本估算结果，保留数量和约定业务输入；资料不足或验证失败则全部不变，不创建任何资金、需求、预占或仓储作业。
- [ ] 提交边界再次检查状态及所有副作用，预览后已付款/预占/下发时拒绝。成功操作重试不重复更正历史，竞争下不能形成部分行更新。
- [ ] 历史标准订单仍不受后续改配影响；更正后查看订单可区分最初解析结果与本次人工更正，不依赖当前映射反查历史。
- [ ] HTTP API 覆盖合法早期更正、每种阻塞条件、状态竞争、事务失败、租户/店铺权限、原始负载及当前配对不变；网页完成预览、原因填写、确认、审计查询和被阻止案例。

## Comments

本期不实现已付款、已预占、已建计划/下发或已发货订单的换 SKU 回滚/补偿。仓储质量撤拣退检是独立用例，不能借用其解除预占接口完成普通更正。
