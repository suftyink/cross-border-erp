# 02: SKU 启停、身份锁与有效商品契约

Status: ready-for-agent

**What to build:** 商品维护人员能单个或批量启停 SKU，系统可靠限制身份变更与删除，并为采购、订单、配对提供统一的有效 SKU 查询及校验能力。

**Blocked by:** 01：SKU 草稿建档与两个维护入口。

- [ ] 实现 DRAFT → ACTIVE ⇄ INACTIVE；保存草稿与「保存并启用」动作分开，不经过独立审核。启用校验编码、名称、SPU、分类和基本单位，品牌、图片、重量和申报资料不是基础启用必填。
- [ ] 独立列表与 SPU 详情都显示状态及可执行操作；支持批量启用/停用，给出明确结果。启停使用商品维护权限，不增加单独审批权限。
- [ ] 可靠保存「曾启用」事实。首次启用或出现业务引用后，编码、所属 SPU、规格身份及基本库存单位不可直接改变；停用再操作仍保持锁定。
- [ ] 只允许删除从未启用且无引用的草稿。已有采购、订单、库存/流水、收发货、退货、FBA 等引用即使余额为零或单据关闭也受保护；旧数据引用不能漏判。
- [ ] 描述性资料仍可按规则编辑。通过旧 ProductVariant 激活/更新接口、SPU 发布或其他既有商品入口不能绕过 SKU 状态及身份锁；变体与 Sku 具有明确的同一库存身份关联。
- [ ] 提供跨域公共有效 SKU 查询与批量校验契约，区分不存在、跨租户、不完整或未启用等原因；查询返回稳定身份、代码、显示资料和状态。引用事实通过所属领域契约协作，不跨域依赖内部 Store。
- [ ] 字典或父级编辑不能间接破坏锁定身份。竞态下启用、删除、修改和新引用不能同时突破约束；关键检查在写入边界生效。
- [ ] 对现有状态、曾启用事实及变体关联先检查冲突；只迁移证据明确的数据，无法证明的旧身份列出待修复项，不以当前停用推断从未启用。
- [ ] HTTP API 覆盖启用缺项、无需审批、停用后锁定、删除条件、旧入口绕过、越权及竞争边界；网页完成单个/批量启停、锁定提示和受控草稿删除。

## Comments

本任务提供新业务准入基础；采购和订单各个生效关口的接入及存量履约例外分别在 08、09 验收。不得把「停用」实现为删除映射或禁止所有历史作业。
