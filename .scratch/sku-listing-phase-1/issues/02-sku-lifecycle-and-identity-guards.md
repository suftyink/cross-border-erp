# 02: SKU 启停、身份锁与有效商品契约

Status: resolved

**What to build:** 商品维护人员能单个或批量启停 SKU，系统可靠限制身份变更与删除，并为采购、订单、配对提供统一的有效 SKU 查询及校验能力。

**Blocked by:** 01：SKU 草稿建档与两个维护入口。

- [x] 实现 DRAFT → ACTIVE ⇄ INACTIVE；保存草稿与「保存并启用」动作分开，不经过独立审核。启用校验编码、名称、SPU、分类和基本单位，品牌、图片、重量和申报资料不是基础启用必填。
- [x] 独立列表与 SPU 详情都显示状态及可执行操作；支持批量启用/停用，给出明确结果。启停使用商品维护权限，不增加单独审批权限。
- [x] 可靠保存「曾启用」事实。首次启用或出现业务引用后，编码、所属 SPU、规格身份及基本库存单位不可直接改变；停用再操作仍保持锁定。
- [x] 只允许删除从未启用且无引用的草稿。已有采购、订单、库存/流水、收发货、退货、FBA 等引用即使余额为零或单据关闭也受保护；旧数据引用不能漏判。
- [x] 描述性资料仍可按规则编辑。通过旧 ProductVariant 激活/更新接口、SPU 发布或其他既有商品入口不能绕过 SKU 状态及身份锁；变体与 Sku 具有明确的同一库存身份关联。
- [x] 提供跨域公共有效 SKU 查询与批量校验契约，区分不存在、跨租户、不完整或未启用等原因；查询返回稳定身份、代码、显示资料和状态。引用事实通过所属领域契约协作，不跨域依赖内部 Store。
- [x] 字典或父级编辑不能间接破坏锁定身份。竞态下启用、删除、修改和新引用不能同时突破约束；关键检查在写入边界生效。
- [x] 对现有状态、曾启用事实及变体关联先检查冲突；只迁移证据明确的数据，无法证明的旧身份列出待修复项，不以当前停用推断从未启用。
- [x] HTTP API 覆盖启用缺项、无需审批、停用后锁定、删除条件、旧入口绕过、越权及竞争边界；网页完成单个/批量启停、锁定提示和受控草稿删除。

## Comments

本任务提供新业务准入基础；采购和订单各个生效关口的接入及存量履约例外分别在 08、09 验收。不得把「停用」实现为删除映射或禁止所有历史作业。


## Answer

完成日期：2026-11-21。

- 独立 SKU 页和 SPU 详情共用单个／批量启停操作，保存草稿与原子「保存并启用」分开；批量逐项返回结果。无独立审批，统一使用 `pdm:product:write`。
- 保存永久曾启用事实和引用锁；编码、所属 SPU、基本单位受控维护。只删除已证明从未启用且未引用的草稿；曾启用或被引用后停用不会解锁。描述性名称可继续维护。
- 在 `erp-common` 提供 `SkuCatalog`、`SkuReferences`、`SkuUsageProbe` 公共契约，来源域解释历史引用并在写入同一事务保留事实。涵盖采购、订单、库存／流水、收发货、退货、FBA、财务及渠道配对；不按关闭状态或零余额排除。编码互斥记录与退役标记保护引用、改码及删除竞争。
- 旧 ProductVariant 绑定唯一 canonical SKU，激活复用生命周期；矛盾旧身份阻断激活。商品入口统一核对登录租户；所有 SPU 整行写用例先锁父行，避免并发写回旧分类。新业务准入在采购／订单的具体接入仍由 08、09 完成。
- V59 仅回填可证明的启用事实及唯一无矛盾的变体关联；未知旧事实保守锁定，网页列出待核实清单。增加按单调序号排序的商品变更记录。未运行实际 ERP 数据迁移或部署。
