# 15: 平台原始订单待配对与手动重处理

Status: ready-for-agent

**What to build:** 平台订单按 MSKU 解析为本地 SKU；未配对时整单留在原始订单队列，配对后由人单个或批量重处理，幂等生成带快照的标准订单。

**Blocked by:** 09：手工订单有效 SKU 选品与存量履约；12：人工商品配对、改配与历史追溯。

- [ ] 平台订单输入与手工本地 SKU 输入模式明确区分，先保留原始负载、渠道、店铺、站点、平台订单号和逐行 MSKU，再调用公共当前配对解析契约；不能直接把 MSKU 复制成订单本地 sellerSku。
- [ ] 任一行未配对或目标停用/不可用时，整单留在原始订单队列，显示具体行及原因；无标准半单、财务、采购需求、库存预占、旧履约计划或 WMS 作业。
- [ ] 队列网页支持按店铺、站点、订单及处理状态查询，显示原始行、阻塞原因与配对跳转。目标停用与从未配对原因可区分，原始数据不丢失。
- [ ] 配对完成不自动重放；有相应订单处理及店铺权限的人员可手动单个/批量重新处理。每张订单原子解析，批量逐单显示成功、仍阻塞、已处理或失败。
- [ ] 全行合法后最多生成一张标准订单，保存每行商品资料及解析时的范围、MSKU、本地 SKU、配对身份/版本和解析时间。只进入原有初始/风控状态，不自动支付、预占或发货。
- [ ] 按租户、渠道、店铺、站点和平台订单号识别原始业务订单；相同订单重复导入/并发处理返回已形成的标准订单引用，不重复业务。不同授权店铺相同平台订单号不会互相误判为重复。
- [ ] 解析中关系或商品状态变化不会生成混合目标或越权结果；已有标准订单的快照不随改配、解除或主数据编辑改变。重复接收不同负载保留接收事实，不静默改写已生效订单。
- [ ] 既有测试原始订单允许按本模型补齐/重建待处理状态，先检查来源和冲突并备份，不伪造不存在的原始 MSKU 或历史配对证据。
- [ ] HTTP API 验证一行未配对的整单无副作用、停用阻塞、配对后手动重试、重复/并发幂等、跨范围身份及快照历史；在实际数据库验证唯一性和回滚。
- [ ] 网页完成导入未配对订单、定位配对、返回队列单个与批量处理、跳转标准订单，确认仍需按原流程支付和履约。

## Comments

依赖人工配对即可交付，不必等待 Excel 配对任务；不引入真实平台同步或自动重放。已有成功标准订单若需换 SKU，转入 16 的独立受控用例。
