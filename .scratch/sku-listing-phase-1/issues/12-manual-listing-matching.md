# 12: 人工商品配对、改配与历史追溯

Status: ready-for-agent

**What to build:** 运营人员在 Listing 页单个或批量确认配对、解除、改配，系统保留历史并向订单提供按明确范围解析当前有效目标的公共契约。

**Blocked by:** 02：SKU 启停、身份锁与有效商品契约；11：Amazon Listing 标识与统一查询入口。

- [ ] 配对必须指定 Amazon 渠道、授权店铺、站点、精确 MSKU 和本租户已启用本地 SKU；ASIN/FNSKU 不是配对必填。一个范围/MSKU 最多一个当前有效目标，本地 SKU 可对应多个 MSKU。
- [ ] 支持单个及批量配对、解除、重新配对和改为另一个有效目标；改配显示旧→新和影响范围，明确确认并填写必要原因后生效，不需先手动破坏旧关系。
- [ ] 相同编码仅推荐候选，用户未确认前不建立关系；不将推荐自动应用到其他店铺或站点。
- [ ] 后端独立要求商品配对权限及对应店铺/租户数据权限；只有该权限的运营人员不能编辑、启停或删除商品主数据，也不能借配对修改 Listing 远端资料。
- [ ] 保留关系的当前状态及变更历史，记录旧/新目标、操作者、时间、来源和原因；不依赖覆盖唯一一行后丢失原值的实现。页面可查看历史与当前目标。
- [ ] 提供按租户、渠道、店铺、站点及 MSKU 解析当前有效配对的跨域公共契约，并能给标准订单保存稳定配对身份/版本及解析时目标。
- [ ] 新配对目标停用、跨租户、并发改配或重复提交有确定结果；不能产生两个当前有效目标。目标后来停用不删除历史关系，但新解析需返回目标不可用原因。
- [ ] 改配或解除不变更已有标准订单，也不产生支付、库存、采购或发货副作用；原先一律拒绝冲突目标的旧断言按受控改配更新。
- [ ] HTTP API 验证单/批配对、同码不自动、解除/改配、唯一性、竞争、权限及旧值追溯；网页完成候选确认、批量配对、改配预览和历史查询。
