# 09: 手工订单有效 SKU 选品与存量履约

Status: ready-for-agent

**What to build:** 订单人员使用已启用本地 SKU 建立手工订单，并保留商品快照；停用后的新需求被阻止，已有支付或实物影响的存量订单按原范围继续履约。

**Blocked by:** 03：共享规格字典与单 SKU 组合维护；05：商品必要属性、图片与分阶段完整性。

- [ ] 手工订单明确以本地 SKU 输入，网页搜索选择本租户已启用商品，显示名称、规格、单位；后端校验身份、状态和完整性，不因输入字符串恰好等于某个编码就猜测平台/手工模式。
- [ ] 创建、新增/改增需求以及未生效订单的支付、生成采购需求、预占、旧履约计划及下发仓储等关口接入准入校验；候选选择后停用或直接 API 调用不能绕过。
- [ ] 商品停用前已支付，或已有预占/仓储作业的订单，只能在原商品、原已生效数量范围继续履约。未支付、未预占且未下发的订单不能因早已建草稿获得豁免；不能在老单追加停用商品需求。
- [ ] 实际查询旧履约计划、预占和 WMS 状态，不仅依赖订单主状态；部分实发或已有计划的订单按真实副作用保护，不能把 CREATED 或 PAID 当作全部履约事实。
- [ ] 订单行保留稳定本地身份及商品资料快照，主数据之后改名、改重量/包装不自动更新已存资料。手工订单不伪造平台配对版本，也不改动真实称重记录。
- [ ] 保留既有支付、风控、WMS 分配/出库与财务规则，选品及商品停用不直接预占、发货或扣库存。原单退货及历史查询继续可用。
- [ ] 调整受本功能影响的旧自由编码夹具为正式 SKU；相关仿真数据可在核对备份后按本模型纠正，不削弱后端校验维持测试通过。
- [ ] HTTP API 验证不存在/停用/越权 SKU、各生效关口、停用前后存量差异、旧计划和部分实发保护及快照；网页完成选品建单、停用后阻止新需求和原生效订单继续履约。

## Comments

保留工作区已有订单页面与接口类型修正。平台 MSKU 解析及待配对流程由 15 接入，更换已有订单 SKU 的受控用例由 16 接入。
