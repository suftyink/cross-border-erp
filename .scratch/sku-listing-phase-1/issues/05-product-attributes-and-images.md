# 05: 商品必要属性、图片与分阶段完整性

Status: resolved

**What to build:** 商品维护人员能维护图片、条码、重量尺寸、包装和申报资料，后续已有业务在真正需要时提示缺项。

**Blocked by:** 02：SKU 启停、身份锁与有效商品契约。

- [x] 支持图片、外部 UPC/EAN 等条码、重量、商品及包装尺寸、箱规/装箱数量、申报资料与备注；展示明确单位，分类和品牌仍来自 SPU。
- [x] 重量、尺寸及金额使用适当小数类型并拒绝非法负值；库存数量仍是整数且只有一个基本库存单位。箱规不产生箱/件换算或库存变动。
- [x] 网页可以上传图片或填写图片 URL，列表/详情正确预览、更新与移除。复用现有文件存储，检查租户、权限、文件类型及大小。
- [x] 上传图片保存稳定对象引用并在查看时取得有效地址，签名链接过期后仍可重新查看；不把一小时有效链接当永久图片地址。外部 URL 不触发服务端任意地址抓取。
- [x] 草稿可以缺少资料；启用仅检查已确认的基础字段。真正依赖重量/申报等资料的已有业务操作在使用点拒绝缺项并指出具体 SKU/字段，不为此新增完整物流或报关流程。
- [x] 编辑描述、重量、图片或包装不改变商品身份或状态；历史单据不随当前主数据查询而改写，后续单据按快照契约读取资料。
- [x] HTTP API 验证可选资料、数值边界、租户/权限、上传校验及稳定图片引用；网页演示上传与 URL 两条路径、保存刷新、修改资料和使用阶段缺项提示。

## Comments

Excel 只导入图片 URL；无 ZIP 对图、图片文件名匹配或保质期/序列号控制。具体单据快照在 08、09 建立，主动刷新在 10 交付。

## Answer

完成日期：2026-11-21。

- SKU 独立列表和 SPU 详情中的 SKU 列表增加「商品资料」，支持草稿、启用及停用商品维护；详情增加资料展示和使用检查。分类与品牌继续继承 SPU，修改资料不改变身份、状态或库存。
- `GET/PUT /pdm/api/in/v1/skus/{id}/details` 读取／整份替换可选资料。`ProductData` 作为共用资料值对象，包含条码、说明、商品／单品包装／外箱尺寸、装箱数量、重量、申报资料、备注及图片。重量统一 kg，尺寸统一 cm；数量为基本单位的正整数，不发生库存换算。
- 使用 BigDecimal 和小数位校验，新增资料接口将小数序列化为字符串，网页使用 stringMode，申报金额可精确维护 16 位整数和 2 位小数。保留旧 SKU 重量／金额／币种列为唯一事实来源，扩展资料以 V62 新表持久化；资料变更记录独立前后快照。
- 图片复用 MinIO，最多 10 张，上传仅支持内容匹配的 PNG／JPEG，单张不超过 5 MB、边长 4096、总像素 1600 万。数据库保存租户所属的稳定 assetId；网页通过鉴权内容接口显示，另提供可重新签发的短期链接接口。移除图片只解除当前引用，保留对象供历史使用。
- 图片上传、附件引用及读取校验登录租户，上传和资料修改沿用 `pdm:product:write`。既有通用文件入口补充对象租户校验，并禁止绕过商品入口上传／删除受管理图片。外部 HTTP(S) URL 仅由浏览器读取，不触发后端抓取，拒绝将临时 MinIO 签名 URL 保存为长期资料。
- 启用仍只检查基础资料；`SkuCatalog.checkUsage/requireUsageData` 分别提供运费、包装与申报的使用阶段校验及资料快照。现有 `/tms/api/v1/shipping-rates/estimate` 可选择按 SKU 和整数数量取重，优先含包装重量、其次商品重量，缺项指出 SKU 和字段；原实测重量路径保留。申报／包装提供准备情况检查，不新增报关或物流下单流程。采购／订单具体快照及刷新留在 08、09、10。
- 编辑弹窗每次打开读取最新资料，加载完成前禁止保存；关闭时忽略迟到响应，打开期间保留未保存输入，避免旧缓存覆盖其他客户端的修改。
